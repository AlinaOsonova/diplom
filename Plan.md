# План тестирования мобильного приложения «Мобильный хоспис»

---

## 1. Цель тестирования

Целью тестирования является обеспечение качества и стабильности мобильного приложения «Мобильный хоспис»:

- Проведёте ручное тестирование мобильного приложения «Мобильный хоспис».
- Составите чек-лист для проверки приложения.
- Распишите тест-кейсы для проверки приложения.
- Автоматизируете проверку тест-кейсов по чек-листу.
- Составите отчёты о тестировании.

---

## 2. Объект тестирования

Приложение даёт функционал по работе с новостями хосписа и включает в себя:

- информацию о новостях и функционал для работы с ними;
- тематические цитаты;
- информацию о приложении.

---

## 3. Границы тестирования

Включено в тестирование:

- Функциональность авторизации;
- Отображение и взаимодействие с новостями;
- Отображение тематических цитат;
- Раздел «О приложении»;
- Навигация между экранами;
- Обработка ошибок (некорректный логин/пароль и т.д.);
- UI/UX-тестирование (тестирование пользовательского интерфейса).

---

Ниже перечислены тест-кейсы, подлежащие автоматизации.

| ID тест-кейса | Название сценария                        | Описание

## 5. Устройства и эмуляторы для тестирования

Эмулятор для автоматизации — **API 29, Android 10.**

---

## 6. Перечень инструментов для автоматизации

Для реализации автоматизированного тестирования будут использованы следующие инструменты:

- **Android Studio** — интегрированная среда разработки (IDE) для создания и отладки Android-приложений;
- **Java 11** — язык программирования для написания тестовых сценариев;
- **Espresso** — официальный фреймворк от Google для UI-тестирования нативных Android-приложений;
- **JUnit 4.13.2** — популярный фреймворк для организации и выполнения модульных и UI-тестов на Java;
- **Gradle** — система сборки проекта, обеспечивающая управление зависимостями и запуск тестов;
- **Allure** — гибкий инструмент для генерации детализированных и визуально понятных отчётов о результатах тестирования.

---

## 7. Риски

| Риск | Меры по снижению |
|------|------------------|
| Нестабильная работа эмулятора | Использовать физическое устройство как основное |
| Отсутствие интернета во время тестов | Проверить обработку offline-сценариев отдельно |
| Ограниченное покрытие автоматизацией | Сфокусироваться на критически важных сценариях |

---

## 8. Интервальная оценка времени

Общая продолжительность работ по тестированию и автоматизации оценивается в **3–4 недели**:

| Этап | Оценка времени |
|------|----------------|
| Изучение приложения, планирование, составление чек-листа | 2–3 дня |
| Написание и ревью тест-кейсов | 3–4 дня |
| Ручное тестирование и фиксация результатов | 4–5 дней |
| Настройка окружения для автоматизации | 1–2 дня |
| Разработка автоматизированных тестов (Espresso + JUnit) | 5–7 дней |
| Интеграция с Allure, генерация отчётов | 2 дня |
| Финальная проверка, оформление документации | 2–3 дня |

Общая оценка: **19–26 рабочих дней**.
